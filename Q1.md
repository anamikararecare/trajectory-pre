# Q1 — Conversational representation organisation

## Research question

> To what extent are conversational state and trajectory variables organised
> across layers and activation subspaces inside language models, and how does
> that temporally manifest across turns in conversations?

Q1 uses the generated corpus under `data/q1_data/<run-id>/`. Raw activation
spaces are never pooled across models.
## The 208-conversation corpus

The minimum Q1 design contains 208 debates, each with 32 responses (16 per
agent), spanning seven model families, eight topics, two role orders, and one
seed. Its 112 self-play conversations pair a model with itself. Its 96
mixed-play conversations pair each of six non-anchor models with the
`qwen2.5-3b` anchor. One agent is prompted to support the topic claim and the
other to oppose it; each receives a central reason, must maintain its assigned
conclusion, and answers the partner in a short self-contained paragraph. The
generation artifact stores four response-token-mean hidden states per model
turn.


## E1 — Layerwise encoding over conversation turn ranges

E1 fits a separate probe for every:

```text
model × Track 1 variable × percentage turn range × available layer
```

There is no activation-snapshot factor. The activation stored by generation is
the mean hidden state over generated response tokens. The default conversation
ranges are:

```text
(0%, 25%]  (25%, 50%]  (50%, 75%]  (75%, 100%]
```

For a 32-response conversation these correspond to response turns 1–8, 9–16,
17–24, and 25–32. Custom percentage boundaries are accepted.

Outer evaluation holds out one topic at a time. Regularisation is selected on
the remaining topics only. Null, metadata/state baseline, activation-only, and
combined models use identical observations and folds. Unless disabled, the
baseline includes an embedding of the complete response, matching the text
available to the response-pooled activation.

Continuous variables report held-topic R², Pearson correlation, Spearman
correlation, and incremental residual correlation. Categorical variables report
balanced accuracy. Core variables are attempted by default; use `--targets all` for the complete registry. Unavailable
or underpowered combinations are recorded explicitly in `e1_skipped.csv`.

## Core variables

The default confirmatory set is: `stance_score`, `stance_gap`; local agreement,
remaining disagreement, affiliation, adversariality, alignment, conflict, and
accommodation indices; trailing-three warmth, dominance, and humility; and
`expressed_valence`, `expressed_arousal`, and `expressed_dominance`. The VAD
variables come from `RobroKools/vad-bert`, a single English text-regression
checkpoint returning `[valence, arousal, dominance]`. Scores are cached by text
SHA-256 under the Q1 run directory. Use `--no-vad` only for runs that explicitly
omit these variables.

## E2 — Temporal manifestation across turns

E2 is the direct temporal extension of E1. It uses the same generated response
rows, variables, text/VAD enrichment, percentage ranges, response-token-mean
activations, model-specific spaces, and held-topic folds. There is no snapshot
factor.

The two analyses are complementary:

1. **Independent-range probes** refit E1 separately within every percentage
   range. These show whether decoding strengthens, weakens, or changes peak
   layer as the conversation develops.
2. **Cross-temporal generalization** fits an activation probe in one range and
   applies that same probe at the same model layer to every range. Each
   source-range/held-topic model is fit once and reused across matrix columns.

With the default quarter ranges, `00-25%`, `25-50%`, `50-75%`, and `75-100%`
serve as early, developing, late, and endpoint phases. Strong off-diagonal
transfer supports a stable state axis. Strong diagonal but weak off-diagonal
performance supports phase specificity. Early-to-late versus late-to-early
differences expose directional reorganisation.

For every model and variable, E2 reports:

- earliest range with reliable decoding;
- peak layer and peak correlation/score in every range;
- signed and positive area under the layerwise decoding curve;
- net, absolute, and fitted layer-of-peak migration;
- diagonal, off-diagonal, forward, reverse, and asymmetric temporal transfer.

Reliability is based on held-topic out-of-fold predictions. The default
topic-block bootstrap uses 500 resamples; a continuous probe is reliable when
its 95% lower correlation bound exceeds zero. A categorical probe is reliable
when the lower bound of its balanced-accuracy improvement over its
held-topic-null prediction exceeds zero.

E2 runs three condition scopes by default: `overall`, `self_play`, and
`mixed_play`. `e2_condition_contrasts.csv` reports mixed-play minus self-play
differences in peak decoding, peak layer, layerwise AUC, off-diagonal transfer,
and temporal asymmetry. These are descriptive contrasts with independently
held-out topics, not randomized causal effects.

## Which Q1 results separate self-play and mixed-play?

E2 explicitly estimates `overall`, `self_play`, and `mixed_play` results and
writes direct descriptive condition contrasts. E1 and E3 currently pool both
conditions in their primary probe and subspace estimates; they retain
condition labels in turn-level/audit data but do not claim a separate
self-versus-mixed estimate.

## Figure map across E1, E2, and E3

- **E1 figures** locate each variable across layers and conversation quarters,
  report the best layer in every cell, and show representative layer curves.
- **E2 figures** show independent temporal strength, full train-range ×
  test-range matrices, reliable onset, peak-layer migration, stability versus
  phase specificity/asymmetry, and self-play versus mixed-play contrasts.
- **E3 figures** show how decoding changes with retained subspace rank, the
  selected family dimensionality, cross-family principal-angle overlap, and
  family-level cross-turn transfer.

## E3 — Variable-family activation subspaces

E3 asks whether related variables are encoded in a small set of shared
activation directions, whether different families use overlapping directions,
and whether those directions remain useful across conversation phases. It uses
the identical generated-turn rows, percentage ranges, response-pooled
activations, core variables, baseline, and held-topic evaluation contract as
E1. There is no snapshot factor and activation spaces are never compared
directly across different models.

The confirmatory families are:

- `stance`: stance score and stance gap;
- `agreement_conflict`: local agreement, remaining disagreement, affiliation,
  adversariality, and observed alignment/conflict/accommodation;
- `personality`: trailing-three perceived warmth, dominance, and epistemic
  humility;
- `expressed_vad`: expressed valence, arousal, and dominance.

For each model × family × turn range × layer, E3 first removes variance
predictable from the E1 text/metadata/state baseline within each training
fold. A multivariate ridge probe then predicts all family variables jointly.
Its predictions are truncated to candidate ranks; by default E3 tests
dimensions 1, 2, 4, and 8 plus the complete family rank. The reported
dimensionality is the smallest rank reaching 90% of the best positive
out-of-topic mean target correlation.

Selected activation bases are descriptive fits on all available rows after
rank selection. Cross-family overlap is reported using principal angles.
Cross-turn transfer is separately evaluated out of topic: train on one
percentage range and test on another, using a fixed rank (default 2). Therefore
overlap describes geometry, while rank curves and transfer provide the
held-topic evidence.

## Run E1–E3 on currently available data

The Q1 loader already uses the intersection of completed transcripts and
activation files. Incomplete planned conversations are skipped unless
`--require-complete` is explicitly supplied. Audit the exact subset with:

```bash
conda run -n traj python -m src.q1.q1_available \
  --run-dir data/q1_data/q1_minimum_v1
```

The flexible launcher writes this audit to `available_corpus.json`, keeps E1,
E2, and E3 in separate result directories, and records one combined log:

```bash
bash scripts/run_q1_available.sh quick \
  data/q1_data/q1_minimum_v1 \
  results/q1/available_quick
```

Profiles:

- `quick`: stance score/gap only, overall-condition E2, 50 reliability
  bootstraps, and no VAD or response-text embeddings. This is preliminary.
- `current`: the complete currently feasible core analysis, VAD and text
  controls enabled, self/mixed E2 contrasts, and 200 bootstraps.
- `full`: the same analysis with the confirmatory 500 bootstraps.

Run or resume one experiment at a time by using a stable output root:

```bash
Q1_EXPERIMENTS=e1 bash scripts/run_q1_available.sh current \
  data/q1_data/q1_minimum_v1 results/q1/available_current

Q1_EXPERIMENTS=e2 bash scripts/run_q1_available.sh current \
  data/q1_data/q1_minimum_v1 results/q1/available_current

Q1_EXPERIMENTS=e3 bash scripts/run_q1_available.sh current \
  data/q1_data/q1_minimum_v1 results/q1/available_current
```

Useful environment overrides include `Q1_MODELS`, `Q1_TURN_RANGES`,
`Q1_TARGETS`, `Q1_E3_FAMILIES`, `Q1_CONDITION_SCOPES`,
`Q1_BOOTSTRAP_SAMPLES`, `Q1_NO_VAD`, `Q1_NO_TEXT_EMBEDDINGS`,
`Q1_SKIP_CROSS_TEMPORAL`, `Q1_ANNOTATIONS`, and `Q1_GEOMETRY_TURNS`.
Missing registered variables are written to each experiment's skipped table.

```bash
Q1_ANNOTATION_MAX_CONVERSATIONS=8 \
```

Continue from that journal and annotate every currently ready conversation:

```bash
bash scripts/q1_annotate_available.sh gpt \
  data/q1_data/q1_minimum_v1 \
  data/q1_data/q1_minimum_v1/q1_annotations
```

For two independent passes, set `Q1_ANNOTATION_PASSES=2`. The default is one
pass because the current ready corpus contains thousands of response-level
items. The output used by Q1 analysis is:

```text
data/q1_data/q1_minimum_v1/q1_annotations/annotations.csv
```

The annotator writes a row-level JSONL journal after every successful item, so
reissuing the same command resumes rather than paying for completed work.
`gpt` requires `OPENAI_API_KEY`; use `claude` with `ANTHROPIC_API_KEY`.

Then run the experiments with:

```bash

  data/q1_data/q1_minimum_v1 \
```
